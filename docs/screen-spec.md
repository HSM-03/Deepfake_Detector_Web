# 화면 명세 (화면설계서 v1.3, 2026-09-29 제출본에서 옮김)

원본은 「2026년도 심화응용프로젝트 화면설계서」. 구현에 필요한 1장·3장·4장·5장의 내용을 옮겼고,
와이어프레임 이미지와 유스케이스 다이어그램은 포함하지 않았다.

## 공통 규격

- 데스크톱 1440×1000 기준, 상단 헤더 고정(`[새 분석]` `[분석 이력]`), 콘텐츠 최대 폭 1200px.
- 판정 표기: 진짜 □ / 가짜 ■ / 보류 ◆ / 불가 ×. 색상은 기본설계에서 확정하며 아이콘·텍스트를 병기한다.
- 차트는 Recharts.
- 결과 화면 하단에 '1차 선별(triage) 도구' 고지 문구 고정.
- 로그인·관리자 화면(UC-13·14)은 설계 범위에서 제외.
- 판정 임계값(S 0.4/0.6, 상충 임계, SQI 하한)과 와이어프레임의 점수·BPM 수치는 모두 예시이며 성능 평가 단계의 실험으로 확정한다.

## 화면 흐름

- 기본 경로: 업로드(SCR-01) → 진행(SCR-02) → 요약(SCR-03) → 근거(SCR-04).
- 전처리 단계에서 얼굴 미검출·길이 부족이면 SCR-06으로, 융합 판정 단계에서 두 축이 상충하면 SCR-07로 분기한다.
- 이력(SCR-05)은 상단 메뉴에서 항상 접근 가능하고, 행의 상태에 따라 SCR-02/03/06/07로 재진입한다.
- 리포트 내보내기(UC-05)는 별도 화면 없이 결과 화면의 버튼으로 처리한다. 범위를 줄여야 할 때 버튼만 비활성화하면 된다.

## SCR-01 영상 업로드

- 유스케이스: UC-01 영상 업로드 및 분석 요청
- 목적: 영상을 업로드하고 형식·용량을 1차 검증한 뒤 분석 작업을 큐에 등록한다.
- 진입: 초기 화면 · `[새 분석]` → 이동: SCR-02
- API: `POST /api/videos` → `{ job_id }`

| 번호 | 구성요소 | 동작·설명 |
|---|---|---|
| ① | 업로드 드롭존 | 드래그&드롭 또는 `[파일 선택]`. 지원 형식(MP4·MOV·AVI·WebM)·최대 500MB·10초 이상 정면 얼굴 권장 조건 안내. |
| ② | 선택 파일 카드 | 썸네일·용량·해상도·fps·길이 표시. 브라우저에서 형식·용량 즉시 검증 → 통과/실패 아이콘. |
| ③ | 분석 옵션 | 이력 저장 여부(기본 ON), 메모(선택, 이력 검색 대상). |
| ④ | `[분석 시작]` | 검증 통과 시에만 활성. 업로드 후 job_id를 받아 SCR-02로 이동. |

예외·상태: 형식·용량 오류(대안 흐름 2a)는 이 화면에서 사유를 표시하고 버튼을 비활성 유지 — 서버까지 가지 않는다.

## SCR-02 분석 진행 상태

- 유스케이스: UC-02 분석 진행 상태 조회
- 목적: Celery 워커가 Redis에 기록한 단계·진행률·중간 결과를 주기적으로 조회해 보여준다.
- 진입: SCR-01 · 이력의 진행 중 건 → 이동: SCR-03 / 06 / 07
- API: `GET /api/jobs/{id}/status` (2초 폴링)

| 번호 | 구성요소 | 동작·설명 |
|---|---|---|
| ①·② | 작업 ID · 5단계 스테퍼 | 업로드·검증 → 전처리·ROI 추적 → 메인 모델 ∥ rPPG(병렬) → 융합 판정. 완료 ✓ / 진행 ● / 대기 번호. |
| ③·④ | 진행률 바 · 단계 로그 | 전체 %와 현재 작업 설명. 완료 단계의 중간 결과(프레임 수, 얼굴 검출률, P_model 등)를 로그로 축적. |
| ⑤ | `[분석 취소]` | 확인 후 작업 revoke. 화면을 벗어나도 분석은 계속됨을 문구로 안내. |
| ⑥ | 완료 토스트 | result_type에 따라 done → SCR-03, failed → SCR-06, hold → SCR-07로 자동 이동. |

예외·상태: 실패 시 스테퍼의 해당 단계를 ×로 바꾼 뒤 SCR-06으로 이동. 취소 시 회색 처리 + `[새 분석]`.

## SCR-03 분석 결과 요약

- 유스케이스: UC-03 분석 결과 요약 조회 (+ UC-05 리포트 내보내기 버튼)
- 목적: 최종 판정·종합 점수·두 축 점수·SQI를 한 화면에서 파악하게 한다. 판정 라벨만이 아니라 '왜'를 같이 보여주는 것이 핵심.
- 진입: SCR-02 완료 · 이력 행 클릭 → 이동: SCR-04 / 05
- API: `GET /api/jobs/{id}/result`

| 번호 | 구성요소 | 동작·설명 |
|---|---|---|
| ① | 최종 판정 카드 | 진짜/가짜/판단 보류 3분류 라벨, 종합 점수 S, 산출식 S=(1−w)·P_model+w·P_rppg 와 적용 w, 자연어 해석. |
| ② | 두 판별 축 점수 | P_model(시각 아티팩트)·P_rppg(생체신호)를 같은 0~1 막대로 나열. 경계 구간 0.4~0.6 점선, 축 간 차이와 상충 임계 비교. |
| ③·④ | SQI 카드 · ROI별 BPM | 신호품질지수와 등급, 구성 요소(얼굴 픽셀·압축·조도·움직임). 이마·좌볼·우볼 추정 심박 비교 미니 차트. |
| ⑥ | 액션 바 | `[판정 근거 상세 보기]` → SCR-04, `[리포트 내보내기(PDF)]` = UC-05, `[결과 링크 복사]`. 하단에 '1차 선별 도구' 고지 고정. |

(원본 표에 ⑤번은 없다.)

예외·상태: SQI < 0.5이면 ③에 경고, ①에 'rPPG 기여도 낮음 — 메인 모델 중심 판정' 표기. 판단 보류는 SCR-07(상태 변형)로.

## SCR-04 판정 근거 상세

- 유스케이스: UC-04 판정 근거 상세 조회
- 목적: 판정이 어떤 신호 수준 근거로 나왔는지 rPPG 파형·스펙트럼·ROI 일관성·모델 프로파일로 검토한다.
- 진입: SCR-03 / 07 → 이동: SCR-03
- API: `GET /api/jobs/{id}/evidence?roi=`

| 번호 | 구성요소 | 동작·설명 |
|---|---|---|
| ①·② | 탭 · ROI 선택기 | rPPG 신호 / 메인 모델 / SQI / 특징 벡터 탭. ROI(전체·이마·좌볼·우볼) 선택 시 차트 재렌더. |
| ③ | 조건부 안내 배너 | w≈0(SQI 낮음)일 때만 표시: 'rPPG 축 기여도 0에 근접, 본 판정은 사실상 메인 모델 단독 결과'. |
| ④ | rPPG 차트 3종 | 원신호(RGB→CHROM) · Butterworth 0.7~4Hz 필터 후 파형 · Welch 파워 스펙트럼(심박 대역 음영, 피크 Hz=BPM 마커). |
| ⑤·⑥ | 일관성 차트 · 특징 표 | ROI별 BPM 비교(σ), 3초 윈도우 BPM 변동, 메인 모델 구간별 프로파일. 특징 6개의 측정값 / 실제 얼굴 기준 / 판단(○△×) 표와 두 축 대조 요약. |

예외·상태: 데이터 로딩 중 차트 영역 스켈레톤. 판단 보류 건은 ⑥에 어느 특징이 상충을 만들었는지 강조.

특징 6개(상세제안서 기능 5): 추정 심박수의 생리학적 범위(45~180 BPM) 여부, 주 피크 SNR, 스펙트럼 엔트로피,
ROI 간 심박수 일치도(BPM 표준편차), ROI 간 위상 일관성, 윈도우별 BPM 변동성.

## SCR-05 분석 이력

- 유스케이스: UC-06 분석 이력 조회 · UC-07 분석 결과 삭제
- 목적: 과거 분석을 검색·필터링해 재조회하고, 선택 건을 삭제하거나 리포트를 일괄 내보낸다.
- 진입: 상단 `[분석 이력]` → 이동: SCR-02 / 03 / 06 / 07 (행 상태별)
- API: `GET /api/jobs?q=&verdict=&…` · `DELETE /api/jobs`

| 번호 | 구성요소 | 동작·설명 |
|---|---|---|
| ①·② | 검색·필터 바 · 판정 칩 | 파일명·작업 ID·메모 통합 검색, 판정/기간/상태/SQI 하한 필터(URL 쿼리 반영). 칩은 판정별 건수 + 필터 토글. |
| ③·④ | 이력 테이블 | 작업 ID / 파일명 / 일시 / 판정(■가짜 □진짜 ◆보류 ×불가 ◐진행) / S / P_model / P_rppg / SQI / 상태. 행 클릭 → 상태별 화면 이동, 진행 중 행은 5초 갱신. |
| ⑤ | 일괄 액션 · 페이지네이션 | 선택 건 리포트 ZIP 내보내기, 삭제(확인 대화상자, UC-07). 페이지당 10/20/50건. |

예외·상태: 결과 없음 → 빈 상태 문구 + `[필터 초기화]`. 업로드 원본은 UC-15(스케줄러)로 자동 삭제되지만 분석 결과·특징 데이터는 이력에 남는다.

## SCR-06 분석 불가 안내

- 유스케이스: UC-16 분석 불가 안내 (UC-08 확장)
- 목적: 얼굴 미검출·길이 부족 등으로 분석이 중단된 사유를 수치와 함께 알리고 재시도 방법을 제시한다.
- 진입: SCR-02 failed · 이력의 불가 건 → 이동: SCR-01 / 05
- API: `GET /api/jobs/{id}/result` (failed)

| 번호 | 구성요소 | 동작·설명 |
|---|---|---|
| ① | 안내 헤더 | 사유를 한 문장 제목으로(얼굴 미검출 / 길이 10초 미만 / 파일 손상 등) + 중단 단계(n/5). |
| ② | 중단 사유 상세 | 기준 대비 측정값: 예) 얼굴 검출 프레임 5.3% < 기준 80%, 얼굴 크기 42×48px < 기준 80×80px. |
| ③·④ | 해결 방법 · 버튼 | 사유 코드별 권장 조치(정면 얼굴 구간 10초 이상, 720p 이상). `[다른 영상 업로드]` `[이력으로]`. |

예외·상태: 분석 불가 건도 이력에 '분석 불가' 상태로 기록되어 사유를 다시 볼 수 있다.

## SCR-07 판단 보류 결과

- 유스케이스: UC-17 판단 보류 처리 (UC-12 확장)
- 목적: SQI가 충분한데 두 축이 크게 상충하면 임의 판정 대신 '판단 보류'를 명시하고, 검토자의 최종 판단을 기록받는다. SCR-03과 같은 레이아웃의 상태 변형.
- 진입: SCR-02 hold · 이력의 보류 건 → 이동: SCR-04 / 05
- API: `GET …/result` · `POST /api/jobs/{id}/review`

| 번호 | 구성요소 | 동작·설명 |
|---|---|---|
| ① | 판정 카드(보류 변형) | '판단 보류(재검토 필요)' 라벨, S는 '—'. 보류 조건(SQI ≥ 임계 AND \|P_model − P_rppg\| ≥ 임계)을 수치로 표시. |
| ② | 두 축 점수(상충 표시) | 두 막대 사이 차이를 화살표로 연결해 상충 정도를 시각화. 임계값은 실험으로 결정, 설정(UC-13)에서 조정. |
| ③ | 검토자 최종 판단 기록 | 진짜 / 가짜 / 추가 검토 필요 라디오 + 사유 메모 → 저장 시 이력 상태 '재검토 → 검토 완료'. |
| ④ | 액션 바 | SCR-03과 동일. 보류 건은 이력 '재검토' 필터로 모아 볼 수 있음을 안내. |

예외·상태: 기록 후 ③은 읽기 전용 카드('검토자 판단: 가짜, 일시, 사유') + `[수정]`으로 바뀐다.

## 판정 규칙 (상세제안서 기능 6)

- `S = (1 − w) · P_model + w · P_rppg`, `w = α · SQI` (α는 실험으로 결정).
- SQI가 낮으면 w가 0에 수렴해 사실상 메인 모델 단독 판정이 된다.
- SQI가 충분히 높은데 `|P_model − P_rppg|`가 임계치를 넘으면 '판단 보류(재검토 필요)'.
- 최종 결과는 진짜 / 가짜 / 판단 보류 3분류.
