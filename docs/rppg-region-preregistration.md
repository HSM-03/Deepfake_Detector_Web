# rPPG 분류기 개선(부위별 맥박 비교) — 사전 등록

이 문서는 **결과를 보기 전에** 정한 규칙이다. 작업을 시작하기 전에 커밋하고, 이후 바꾸지 않는다.
바꿔야 하면 본문을 고치지 않고 맨 아래 "변경 기록"에 이유와 함께 덧붙인다(결과를 본 뒤의 변경인지 밝힌다).

- 작성: 2026-10-28. 브랜치 `feat/rppg-region`. 이전 사전 등록: `docs/stage5-preregistration.md`(5단계 5-0~5-5, 그대로 유효).
- 작업 노트북: **작업을 이어받는 팀원의 노트북**(인수인계 목록: `docs/backend-plan.md` "0-1. 인수인계").

## 0. 배경과 가설

- 5단계 결과: 특징 6개(얼굴 전체 맥박의 요약값) 분류기는 FF++ c0 Deepfakes 시험 쌍에서 AUC 0.577 [0.524, 0.631]로 약했고,
  Celeb-DF는 압축 때문에 SQI가 대부분 낮아 융합 효과가 거의 보이지 않았다. 이 결과만으로는 "rPPG의 한계"가 아니라 "단순한 방식의 한계"로 읽힌다.
- 참고 연구: Seibold 외, "High-quality deepfakes have a heart!" (Frontiers in Imaging, 2025) — 고품질 딥페이크에 원본 영상의 맥박이 남아 얼굴 전체 맥박으로는
  구분이 어렵다고 보고하고, 다음 방향으로 얼굴 부위별 혈류 분포를 제안했다. (인용 전에 원문을 확인한다.)
- **가설**: 얼굴을 교체한 가짜는 합성된 안쪽 얼굴과 원래 그대로인 바깥쪽(이마 위쪽·얼굴 가장자리·목)의 맥박 타이밍이 어긋난다.
- 효과가 없으면 "얼굴 전체 + 부위별 두 방식으로 시험한 rPPG의 한계 분석"으로 정리한다. **결과가 약해도 그대로 기록한다.**

## 1. 사용 시나리오와 오류 우선순위

1. **사용 시나리오**: 공유하거나 믿기 전에 의심 영상을 걸러내는 1차 검사.
2. **오류 우선순위**: 가짜를 놓치는 오류를 더 중요하게 본다.
   - **놓친 것** = 가짜인데 '진짜'로 판정된 것. 가짜를 '가짜' 또는 '판단 보류'로 판정하면 둘 다 사람 검토로 넘어가므로 **걸러낸 것**으로 센다.
   - **진짜 오판** = 진짜를 '가짜' 또는 '판단 보류'로 판정한 것.

## 2. 주 평가 지표

- **진짜 오판율 ≤ 10%** 인 조건에서 **가짜 놓침률이 가장 낮은 것**을 고른다(상한 10%, 2026-10-28 확정).
- 모든 비율은 **편수와 95% 신뢰구간**(윌슨 구간)을 같이 보고한다.
- 판단 보류 비율 상한 20%(5단계 사전 등록 5절)는 유지한다. 판단 보류 비율 = 보류 ÷ 전체.
- 상한(진짜 오판율 10%, 보류 20%)을 모두 만족하는 후보가 없으면, **진짜 오판율이 가장 낮은 후보**를 고르고 "상한 미충족"으로 기록한다.
  같으면 가짜 놓침률이 낮은 후보, 그래도 같으면 보류가 적은 후보.

## 3. 판정 규칙 — rPPG 비대칭 규칙 (상세제안서 대비 설계 변경)

**원칙: rPPG는 어떤 경우에도 '진짜' 판정을 만들지 않는다.**

| 메인 모델 판정 | 조건 | 최종 판정 |
|---|---|---|
| 진짜 | SQI ≥ 하한 이고 P_rppg ≥ τ (rPPG 이상 신호) | **판단 보류**로 올림 |
| 진짜 | 그 밖 | 진짜 |
| 가짜 | SQI ≥ 하한 이고 rPPG 정상(\|P_model − P_rppg\| ≥ 상충 임계, 기존 상충 규칙) | **판단 보류** |
| 가짜 | 그 밖 | 가짜 |

- 메인 모델 판정은 작업 1에서 정하는 기준선으로 P_model에서 낸다. τ는 개발 검증 데이터(②)로 정한다.
- 가짜 → 판단 보류는 시나리오상 둘 다 사람 검토라 주 지표에 영향이 없고, 진짜 영상을 가짜로 단정하지 않는 장점이 있어 유지한다.
- **rPPG로 '진짜'로 내리는 경우는 없다.**
- **설계 변경**: 상세제안서의 S = (1 − w)·P_model + w·P_rppg (w = α·SQI) 가중 평균은 **판정에서 빼고 화면 표시용으로만 남긴다.**
  (가중 평균은 rPPG가 판정을 '진짜' 쪽으로 내릴 수 있어 원칙과 맞지 않는다.) 서비스 반영은 12주차, API 형식을 바꿔야 하면 먼저 알린다.
- **한계**: 두 번째 메인 모델(FF++를 학습하지 않은 모델)이 없으면, FF++ 가짜에 대해 메인 모델 판정이 의미가 없어
  **"진짜 → 판단 보류로 올리는 규칙"이 가짜를 실제로 얼마나 더 걸러내는지 측정할 데이터가 없다.** Celeb-DF는 SQI가 낮아 이 규칙이 거의 작동하지 않는다.

## 4. 데이터 역할 (꼭 지킨다)

| 용도 | 데이터 | 사용 |
|---|---|---|
| ① 학습 | FF++ c0, **학습 조작 방식 Deepfakes·FaceSwap**. 기존 학습 묶음(4-1 25쌍 포함) | 계속 |
| ② 개발 검증 | 기존 시험 묶음: Deepfakes(기존 시험 96쌍) + **처음 보는 조작 방식 FaceShifter·Face2Face·NeuralTextures** | 여러 번 |
| ③ rPPG 최종 시험 | FF++ c0 **새 묶음**, 처음 보는 조작 방식 FaceShifter·Face2Face·NeuralTextures, ①②와 사람 안 겹침 | 13주차 고정 후 **1번** |
| ④ 시스템 최종 평가 | Celeb-DF 평가 세트 518편 + 팀원 영상 | 13주차 고정 후 **1번** |

- **묶음 단위로 나눈다**: FF++ 쌍 목록의 한 줄 [a, b]에서 모든 조작 방식의 가짜 a_b·b_a가 나온다. 같은 두 사람이 얽힌 쌍은 항상 같은 덩어리에 둔다.
  - ① = 5단계 학습 묶음(`docs/stage5/ffpp_split.json`의 `train_old25` + `train_new`), ② = 5단계 시험 묶음(`test`),
    ③ = 나머지 묶음(4-1 번호가 든 묶음과 ①② 제외 약 387묶음)을 `filelist.json` 순서대로 놓고 **시드 1**로 섞은 앞 **50묶음(100쌍)**.
    ③ 목록은 **받기 전에** 커밋한다.
- **③과 ④는 13주차 고정 전까지 열지 않는다.** ③은 12주차에 받아 신호만 저장하고, 파일 지문(sha256)만 커밋한다. 개발 중 판단은 전부 ②로만 한다.
- 쌍 수(조작 방식별): ① DF 125 + FS 125 / ② DF 100(제외 규칙 후 96) + FaceShifter 100 + F2F 100 + NT 100 / ③ FaceShifter 100 + F2F 100 + NT 100.
- 제외 규칙(5단계와 같음): 쌍의 두 영상 중 하나라도 열 수 없거나, 10초 미만이거나, 얼굴 추적률 70% 미만이면 뺀다. 뺀 쌍은 개수와 이유를 적고 다른 쌍으로 채우지 않는다.
- **개발 중 확인용(설정을 고르는 데 쓰지 않음)**: UBFC 3명(부위를 나눠도 심박 오차가 1.5BPM 수준인지), 직접 찍은 원본 8편(진짜를 가짜로 의심하지 않는지).
- FF++는 rPPG 특징 분석과 P_rppg 분류기 학습·시험에만 쓴다(c0, Deepfakes·FaceSwap·FaceShifter·Face2Face·NeuralTextures). 메인 모델·융합·최종 평가 금지는 그대로.

## 5. 작업 1 — 판정 기준선 재결정 (Celeb-DF 검증 세트 197편만)

- 데이터: 5-5 검증 세트(평가 세트 밖, 진짜 98·가짜 99, 얼굴 미검출 3편 제외). 저장된 P_model·P_rppg·SQI로 다시 계산한다(새 분석 없음).
- 후보: **(A)** 진짜 ≤ 0.4 / 가짜 ≥ 0.6, 경계 구간은 진짜·가짜·보류 중 하나 **(B)** 기준선 하나 t = 0.4 / 0.5 / 0.6 / 0.7.
  각 후보에 3절의 비대칭 규칙을 적용한다(τ는 ②로 정하기 전이므로 작업 1에서는 기존 상충 규칙만 적용하고, τ가 정해지면 같은 표로 다시 계산해 기록한다).
- 선택: 2절 규칙(진짜 오판율 ≤ 10% 안에서 가짜 놓침률 최소, 보류 ≤ 20%).
- 보고: 진짜·가짜 편수, 진짜 오판율·가짜 놓침률·보류 비율의 편수와 95% 신뢰구간. 5-5 결과(경계 구간 = 가짜)는 "재결정 전"으로 남긴다.

## 6. 작업 2 — 부위별 맥박 신호 저장

- 부위: 합성되는 안쪽 얼굴(눈·코·입·볼 안쪽), 이마 위쪽, 왼볼, 오른볼, 얼굴 가장자리(턱선·관자놀이 띠), 목(턱 아래 추정 상자), 배경(대조군).
- 영상마다 저장: 프레임별 부위 평균 RGB, 부위별 픽셀 수, 추적 여부, fps, SQI, 영상 정보 — 맥박 지도(부위 × 시간)를 만들 수 있는 형태. 얼굴 이미지는 저장하지 않는다.
- **목 부위**: UBFC·직접 찍은 영상에서 목 신호의 심박이 맞는지 보고 쓸지 정한다. **③을 열기 전에 확정**한다.

## 7. 작업 3 — 부위 간 비교 특징 (필수)

- 후보 특징 2개(이 둘로 고정):
  1. **안쪽–바깥쪽 맥박 위상 차이**: 안쪽 얼굴과 바깥쪽(이마 위쪽·얼굴 가장자리, 목은 6절 결정에 따름) 신호의 심박 주파수에서의 교차 스펙트럼 위상 차이 크기.
  2. **안쪽–바깥쪽 신호 일치도**: 심박 대역(0.7~4Hz) 안의 상관(4-1에서 모든 묶음에서 같은 방향으로 나온 '부위 간 신호 일치도'를 안쪽–바깥쪽으로 바꾼 것).
- 모델: 로지스틱 회귀(5단계와 같은 방식 — 학습 쌍 안 교차검증으로 C 선택, 묶음 단위). 비교: 기존 특징 6개 / 새 특징 2개 / 둘을 합친 것.
- 보고: 학습 조작 방식(DF·FS)과 처음 보는 조작 방식(FaceShifter / Face2Face / NeuralTextures)을 **따로**.

## 8. 계속 여부 결정 (11주차 말)

- 기준(②의 **FaceShifter** 쌍, 쌍 단위 부트스트랩 2,000회): **(a)** 새 특징 모델(새 특징 2개 또는 합친 것 중 학습 쌍 교차검증으로 미리 고른 하나)의
  AUC 95% 신뢰구간 하한 > 0.6 **그리고** **(b)** 기존 특징 6개 모델 대비 AUC 차이의 95% 신뢰구간 하한 > 0.
- 둘 다 만족하면 계속(작업 4 선택, 12주차 서비스 연결). 아니면 멈추고 분석을 정리한다(지금 서비스 유지).
- Face2Face·NeuralTextures(표정 조작)는 같은 지표로 따로 보고하고 결정에는 쓰지 않는다.

## 9. 작업 4 — 선택 (8절 기준을 넘을 때만)

- 맥박 지도 + 작은 CNN. **맥박 때문인지 확인하는 대조 실험**을 함께 한다:
  (1) 심박 대역(0.7~4Hz)을 지운 지도 — 성능이 그대로면 맥박이 아니다 (2) 부위별 시간 축을 무작위로 어긋나게 섞기 — 타이밍 정보만 없애면 떨어지는지
  (3) 배경 부위만으로 학습 — 성능이 나오면 합성 경계의 깜빡임 같은 비맥박 흔적.
- FF++를 학습하지 않은 두 번째 메인 모델: **후보 조사만**(FF++ 학습 포함 여부와 근거, 가중치 공개, 라이선스, CPU 처리 시간). 설치하지 않는다.
  쓰게 되면 FF++를 융합 평가에 쓰는 것이므로, 규칙을 바꾸는 이유를 그때 계획서에 먼저 적는다.
- 일정이 밀리면 작업 4부터 뺀다.
